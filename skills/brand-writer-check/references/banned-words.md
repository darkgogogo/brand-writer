# 禁用词三级清单

> V2 重构：从"第一/二/三类"的一刀切模式升级为「引用自动豁免 + 词表三级」机制。详见 `brand-writer-check` SKILL.md 的 L1 处理流程。

## 🔴 第一级：强禁（必改，硬拦截）

绝对 AI 腔标志性表达，命中即必须改。任何上下文都不允许。

### 结构型套话
- 从 X 到 Y（"从理论到实践"、"从 0 到 1"、"从 A 到 B"等固定句式）
- 不仅 X，还 Y
- 在 X 的当下
- 如今这个时代

### 情绪叠加词
- 不得不说
- 毋庸置疑
- 屡试不爽
- 妥妥的
- 稳稳的

### AI 标志性修辞
- 犹如 / 宛若 / 恰似（文学调夸饰）
- 不啻为
- 堪称 X 的典范
- 令人拍案叫绝

### 过度技术腔
- 赋能
- 打造闭环
- 实现从 X 到 Y 的跃迁

### 逻辑/叙事 AI 腔（写作时也要实时规避）
合并自 `brand-writer-article/references/writing-checklist.md` 的"绝对禁用"词表：

- 说白了
- 本质上
- 换句话说
- 意味着什么 / 这意味着
- 不可否认
- 值得注意的是
- 不难发现
- 众所周知
- 综上所述 / 总的来说
- 首先...其次...最后（起手连用式）

替代写法参考：
- 说白了 → 其实 / 换个说法
- 本质上 → 说到底 / 关键是
- 换句话说 → 也就是说 / 意思就是
- 意味着什么 → 结果就是 / 所以呢

## 🟡 第二级：条件禁（提示不拦，人工判断）

空泛口号词，特定语境可以用（产品官方公告、功能页描述）。命中后 self-check 只提示不阻塞。

- 精准
- 全方位
- 一站式
- 高效
- 无缝
- 深度
- 沉浸式
- 极致
- 定制化
- 智能化

使用原则：
- 用官方调性（`official`）写时 → 可用，但频率 <3 次/篇
- 模仿博主（`mimic_blogger`）写时 → 尽量改成博主的具体表达
- 自由写（`free`）时 → 看主题决定

## 🟢 第三级：弱禁（记录不报，供统计）

一般修饰性过度词。偶尔用不影响。频次过高（>5 次/千字）自检报告警示。

- 十分
- 非常
- 特别
- 相当
- 蛮
- 超（做程度副词时）

## 博主专属禁用（动态加载）

当 `style_source == "mimic_blogger"` 时，额外加载 `style-reports/<platform>/<博主>.md` 里的「禁用词清单」section，合并到第一级强禁。

## 执行规则

### 1. 引用自动豁免（Layer A）
L1 扫描前先剔除以下内容，不参与匹配：
- `^>` 开头的 blockquote 行
- ` ``` ` 包裹的代码块（多行）
- `` ` `` 包裹的行内代码
- YAML frontmatter（`---` 之间）

### 2. 三级分类输出
- 🔴 命中 → **必改**（阻塞，L2 不开工）
- 🟡 命中 → **请复核**（提示，不阻塞）
- 🟢 命中 → **提示**（仅记录，不显式报）

### 3. 优先级（D14）
**默认**：未显式登记的词一律以本文件为准；profile 的一般性"允许表述"不能覆盖本文件的禁用。

**例外**：profile 可新增 `## 豁免词` section 显式登记产品专属豁免。经 review 后 brand-writer-check L1 Layer B 会**直接从词表中剔除**这些词（不匹配、不报、不提示），只在 L1 section 末尾追加一行 `> 本次自检已豁免 profile 登记词：X 个`。

**profile 豁免词登记格式**（brand-writer-check L1 Layer B 加载此 section）：

```markdown
## 豁免词

- 深度：focusflow 官方文案「深度专注模式」是产品术语，保留
- 打造：2025-12 发布公告里用过「为知识工作者打造」已审定稿，保留
```

格式规则：
- section 标题必须精确为 `## 豁免词`（方便脚本解析）
- 每条一行 `- <词>：<豁免理由>`，理由必填（方便 review 时判断是否仍适用）
- 只对当前 profile 生效，不改本文件全局清单
